API авіаційних даних

Аеронавігаційні дані FAA — аеропорти, злітно-посадкові смуги, навігаційні точки, повітряний простір та офлайн-карти. Усі ендпоінти нижче працюють на цьому сервері; приклади — живі посилання, які можна відкрити в браузері.

Пошук по базі

Введіть код FAA або назву міста — і подивіться, що є в базі. Це та сама база, з якою працюють ендпоінти нижче. Дані охоплюють лише США (джерело — FAA), тож європейських аеропортів тут немає.

Аеропорти

Дані з PostgreSQL. Аеропорти ідентифікуються за кодом FAA (LAX, JFK, 0J0) — не за чотирилітерним кодом ICAO.

GET /api/v1/airports

Список аеропортів із пагінацією та необовʼязковими фільтрами.

ПараметрОпис
stateДволітерний код штату, напр. CA
countryДволітерний код країни, напр. US
cityЧастина назви міста, без урахування регістру
qПочаток ідентифікатора, напр. 0J
page, per_pageПагінація; per_page — максимум 500
/api/v1/airports?city=chicago&per_page=5
GET /api/v1/airports/<identifier>

Один аеропорт з усіма його смугами. Регістр коду не має значення.

/api/v1/airports/LAX
GET /api/v1/airports/near

Аеропорти навколо заданої точки, найближчі першими. Кожен результат містить поле distance_km.

ПараметрОпис
lat, lonОбовʼязково. Десяткові градуси
radius_kmРадіус пошуку, за замовчуванням 50, максимум 500
limitМаксимум результатів, за замовчуванням 20, максимум 200
/api/v1/airports/near?lat=40.7128&lon=-74.0060&radius_km=30  — околиці Нью-Йорка /api/v1/airports/near?lat=33.9425&lon=-118.4081&radius_km=25&limit=10  — околиці LAX

Файли даних

Повні набори даних у форматі CSV (gzip), які оновлюються кожного 28-денного циклу FAA. Це завантаження файлів, а не JSON.

GET /api/<flag>/

Один набір даних на прапорець: b — базові аеропорти, c — повітряний простір класів, d — перешкоди, e — простір спеціального використання, f — навігаційні точки, g — стадіони, n — радіонавігаційні засоби, r — торці смуг, t — TFR.

/api/b/  — базові аеропорти (.csv.gz)
GET /api/changes/

Метадані свіжості: коли кожен набір даних востаннє оновлювався і скільки він важить. Клієнти за цим вирішують, чи потрібне повторне завантаження.

/api/changes/

Схеми та карти

Схеми аеропортів та офлайн-тайли карт. Вони синхронізуються з окремого сервера, тому на цьому інстансі списки можуть бути порожніми.

GET/api/v1/a-big

Штати, для яких є повні схеми аеропортів FAA; далі /api/v1/a-big/<state> — перелік кодів, /api/v1/a-big/<state>/<code> — саме зображення.

/api/v1/a-big
GET/api/v1/maps

Доступні офлайн-пакети карт .mbtiles.

/api/v1/maps

Адміністрування

GET /admin потрібен токен

Панель оператора: свіжість наборів даних, розміри файлів та ручний запуск оновлень. Захищено — браузер запитує облікові дані, а JSON-ендпоінти за панеллю вимагають bearer-токен.

Варто знати

  • Ідентифікатори — коди FAA, а не ICAO LAX працює; KLAX — ні. Те саме з JFK проти KJFK.
  • Покриття відповідає джерелу FAA {{ coverage_note }} Джерело — 28-денна підписка FAA, тому дані за побудовою зосереджені на США.
  • Лише читання, звичайний HTTP Усі публічні ендпоінти — GET і не потребують ключа. На цьому інстансі поки немає TLS-сертифіката, тож розглядайте його як тестове середовище, а не як продакшн-ціль для інтеграції.
Джерело даних: FAA National Airspace System Resource (NASR), 28-денна підписка.
